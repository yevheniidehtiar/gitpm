# Zensical reference (for docs of libraries and tools)

Verified on **2026-10-16** against **zensical 0.0.71** (PyPI latest, requires Python >= 3.11),
using `uvx zensical --help`, `zensical new`, and real builds in a scratch directory, plus the
official docs at https://zensical.org/docs/get-started/ and linked pages. Zensical is young
(0.0.x): re-check `uvx zensical --version` and the docs when something here disagrees with
reality, and update this file.

Zensical is a static site generator from the creators of Material for MkDocs. It reads either
`zensical.toml` (native) or an existing `mkdocs.yml`.

## Install

```bash
pip install zensical            # inside a virtual environment
uv add --dev zensical           # recommended in a Python project; run with `uv run zensical ...`
uvx zensical build              # no install at all (good for CI and non-Python repos)
uvx zensical@0.0.71 build       # pinned
```

Notes: do not use uv's symlink link mode with Zensical. Conda-forge and an official Docker image
exist (the Docker image is for preview/build, not hosting). For a non-Python repo (TypeScript,
Rust, Go), prefer `uvx zensical@<version>` so no Python project files are needed.

## CLI (confirmed with `--help`)

| Command | Purpose | Flags |
|---|---|---|
| `zensical new [DIRECTORY]` | Scaffold `zensical.toml`, `docs/index.md`, `docs/markdown.md`, `.github/workflows/docs.yml`. Fails if `zensical.toml` already exists; never overwrites other files. | none |
| `zensical serve` | Build and serve with live reload at `http://localhost:8000` | `-f/--config-file PATH`, `-a/--dev-addr IP:PORT`, `-o/--open`, `-s/--strict` (documented as currently unsupported for serve) |
| `zensical build` | Write the static site to `site_dir` (default `site/`) | `-f/--config-file PATH`, `-c/--clean` (clear cache), `-s/--strict` (abort on warnings) |
| `zensical --version` | Print version | |

Strict mode: reports all issues, then exits with status 1 (confirmed: a broken page link and a
broken `#anchor` were each reported with file:line:col and the build aborted). A Python traceback
ending in `RuntimeError: Aborted because --strict flag is set` follows the report; ignore the
traceback, read the warnings above it. Use `--clean` in CI and after upgrades; the cache can
hold stale state.

Not provided vs MkDocs: `gh-deploy` (use a workflow), `get-deps`, `--theme`, `--site-dir`,
`--use-directory-urls` (set `site_dir`, `use_directory_urls` in config instead).

## `zensical.toml`

Everything lives under the `[project]` table. Confirmed keys (generated by `zensical new` or
accepted in a strict build):

| Key | Meaning |
|---|---|
| `site_name` | Header title |
| `site_url` | Public URL; include the sub-path for project pages. Required for `navigation.instant`, sitemap, canonical URLs |
| `site_description`, `site_author`, `copyright` | Metadata; `copyright` accepts HTML entities |
| `repo_url`, `repo_name` | Repo link in header (stars/latest release shown for public GitHub/GitLab) |
| `edit_uri` | Path joined onto `repo_url` for edit links, e.g. `"edit/main/docs/"` |
| `docs_dir` / `site_dir` | Source (default `docs`) and output (default `site`) |
| `nav` | Array of strings or inline tables, see below |
| `strict` | `true` = same as `--strict` |
| `extra_css`, `extra_javascript` | Lists of files relative to `docs_dir` |
| `exclude_docs`, `draft_docs` | Patterns left out of the build (drafts still show in preview) |
| `use_directory_urls` | Pretty URLs (`/page/`) vs `/page.html` |

Tables: `[project.theme]` (`variant`, `language`, `features`, `logo`, `favicon`, `custom_dir`),
`[project.theme.font]` (`text`, `code`), `[project.theme.icon]`, `[[project.theme.palette]]`
(array of tables), `[[project.extra.social]]` (`icon`, `link`), `[project.validation]`,
`[project.markdown_extensions]`.

### nav

```toml
[project]
nav = [
  { "Home" = "index.md" },
  { "Guides" = [ "guides/index.md", "guides/deploy.md" ] },
  { "Changelog" = "https://github.com/org/repo/releases" },
]
```

Plain strings are page paths relative to `docs_dir`; an entry that is not a Markdown page is an
external URL. With `navigation.indexes`, a section's `index.md` (listed first) is the section
landing page. Omit `nav` to get an automatic nav from the file tree (usually worse; write it).

### Theme variant and palette

`variant = "modern"` (default look) or `"classic"` (Material for MkDocs look; pick it when
migrating a Material site with custom CSS/JS). Light/dark/auto toggle (confirmed in the template):

```toml
[[project.theme.palette]]
media = "(prefers-color-scheme)"
toggle.icon = "lucide/sun-moon"
toggle.name = "Switch to light mode"

[[project.theme.palette]]
media = "(prefers-color-scheme: light)"
scheme = "default"
toggle.icon = "lucide/sun"
toggle.name = "Switch to dark mode"

[[project.theme.palette]]
media = "(prefers-color-scheme: dark)"
scheme = "slate"
toggle.icon = "lucide/moon"
toggle.name = "Switch to system preference"
```

Primary/accent colors (`primary`, `accent` inside a palette table, as in Material) were not
verified here; see https://zensical.org/docs/setup/colors/.

### Theme features (what each does)

Confirmed in the generated template and nav docs. Include only what you want.

| Feature | Effect |
|---|---|
| `content.action.edit` / `content.action.view` | "Edit this page" / "View source" buttons (derived from `repo_url` + `edit_uri`). Make the edit button visible. |
| `content.code.copy` | Copy button on every code block |
| `content.code.annotate` | Numbered annotations in code (`# (1)!` + list below) |
| `content.code.select` | Select-by-line support in code blocks |
| `content.tabs.link` | Same-named tabs stay in sync across the site (pick `pip` once) |
| `content.tooltips`, `content.footnote.tooltips` | Tooltips for abbreviations and footnotes |
| `navigation.instant` (+ `.prefetch`, `.progress`) | SPA-style navigation; requires `site_url` |
| `navigation.tracking` | URL follows the active heading |
| `navigation.tabs` (+ `.sticky`) | Top-level sections as header tabs on wide screens |
| `navigation.sections` | Top-level groups rendered as sidebar headings |
| `navigation.indexes` | Section `index.md` becomes the section page. Incompatible with `toc.integrate` |
| `navigation.path` | Breadcrumbs |
| `navigation.prune` | Smaller HTML on big sites. Incompatible with `navigation.expand` |
| `navigation.expand` | Expand all subsections |
| `navigation.footer` | Previous/next links in footer |
| `navigation.top` | Back-to-top button |
| `toc.follow` / `toc.integrate` | Sidebar follows the active heading / TOC inside the left sidebar |
| `search.highlight` | Highlight search terms on the target page |
| `announce.dismiss` | Dismissible announcement bar |
| `header.autohide` | Hide header on scroll |

Search is built in and enabled by default (produces `search.json`); no plugin entry needed.

### Markdown extensions

In TOML, each extension is a dotted key; `{}` means "enabled with defaults".

```toml
[project.markdown_extensions]
admonition = {}
attr_list = {}
md_in_html = {}
toc.permalink = true
pymdownx.details = {}
pymdownx.highlight.anchor_linenums = true
pymdownx.snippets.base_path = ["."]
pymdownx.superfences.custom_fences = [
  { name = "mermaid", class = "mermaid", format = "pymdownx.superfences.fence_code_format" },
]
pymdownx.tabbed.alternate_style = true
```

Note: the generated template enables superfences only through the `custom_fences` key, and uses
`pymdownx.tabbed.alternate_style = true` for the modern tab look (output class `tabbed-alternate`).

Syntax each enables (admonitions, tabs, grid cards and the code block features were rendered in a
scratch build and found in the HTML: `admonition tip`, `<details class="note">`,
`tabbed-set tabbed-alternate`, `grid cards`, `hll` line highlight; annotation markers are
processed client-side so only the source form was confirmed):

````markdown
!!! warning "Title"
    Indented body. Types: note, tip, info, warning, danger, example, quote.

??? note "Collapsed by default"      <!-- pymdownx.details -->
    Hidden until clicked. Use ???+ to open by default.

=== "pip"                             <!-- pymdownx.tabbed -->

    ```bash
    pip install tool
    ```

=== "uv"

    ```bash
    uv add tool
    ```

```python title="app.py" hl_lines="2" linenums="1"
import tool
tool.run()  # (1)!
```

1. Annotation text appears as a popover (content.code.annotate).

<div class="grid cards" markdown>     <!-- attr_list + md_in_html -->

-   **Title**

    ---

    Body text. [Link](page.md)

-   **Another**

    ---

    Body.

</div>

[Primary button](start.md){ .md-button .md-button--primary }   <!-- attr_list -->

--8<-- "examples/hello.py"            <!-- pymdownx.snippets: include a real file -->
````

Mermaid diagrams: a fenced block with language `mermaid` (needs the `custom_fences` entry above).
Icons/emoji shortcodes such as `:material-clock-fast:` need the `pymdownx.emoji` generator and
index lines from the template and, per the grids docs, icon configuration.

### Validation

```toml
[project.validation]
invalid_links = true
invalid_link_anchors = true
unresolved_references = false
unresolved_footnotes = false
unused_definitions = false
unused_footnotes = false
shadowed_definitions = false
shadowed_footnotes = false
```

`[project] validation = false` disables all of it. Pages that exist in `docs_dir` but not in `nav`
did NOT produce a warning in a strict build, so check orphans with `scripts/audit_docs.py`.

## Plugins and compatibility

Zensical has no Python plugin loader like MkDocs. It reimplements popular plugins natively and
silently ignores unlisted ones (their config has no effect, so a missing feature is not an error).
Status per https://zensical.org/docs/compatibility/mkdocs/plugins/ (2026-10-16):

- **Supported:** search (default, most settings ignored), section-index (built in), blog, tags,
  mkdocstrings (also install `mkdocstrings-python`), autorefs, api-autonav, autoapi, macros,
  markdown-exec, include-markdown, meta, redirects, minify, offline, social, rss, glightbox,
  llmstxt, mike (compatible fork needed), awesome-nav, literate-nav, nav-weight, exclude, callouts,
  gh-admonitions, table-reader, markdownextradata, audio, video.
- **Unsupported:** `gen-files` (use autoapi/api-autonav or run generators before the build),
  `open-in-new-tab` (add its JS via `extra_javascript`).
- **Planned / in progress:** `optimize`, `privacy`, `git-authors`, `git-committers`,
  `git-revision-date-localized`.
- **Unsupported setting:** `hooks`.
- Templates use MiniJinja, not Jinja: no arbitrary Python calls in overrides. Material for MkDocs
  9.6.18+ overrides generally work.

Implication for library docs: API reference from docstrings works via mkdocstrings/autoapi; a
"last updated" date per page does not yet (git-revision-date plugins are planned).

## Migrating from mkdocs.yml

1. Keep production as is. Run `uvx zensical build` with the existing `mkdocs.yml`; `nav`, `theme`,
   `extra`, `plugins` and extensions are read as is (confirmed: a minimal `mkdocs.yml` built).
2. Compare pages, nav and search with the old output; check each plugin against the list above.
3. Switch CI commands only when satisfied. Moving to `zensical.toml` is optional; when you do,
   translate `key: value` to `[project]` keys, `theme:` to `[project.theme]`, `palette:` list to
   `[[project.theme.palette]]`, `markdown_extensions:` list to dotted keys, `extra:` to
   `[project.extra]`. Add `variant = "classic"` to keep the Material look.
4. If you want the config to work with both builders, stay on `mkdocs.yml`.

## Common build errors

| Message | Cause and fix |
|---|---|
| `page does not exist` (warning, `file:line:col`) | Link target missing or wrong relative path. Fix the path; link to `.md` files, not URLs. |
| `anchor does not exist` | Heading renamed or slug differs. Slugs are lowercase, hyphenated, punctuation dropped; check the rendered ID. |
| `error reading page metadata '<file>': metadata mapping keys must be strings` | Front matter is invalid YAML, typically an unquoted `{{PLACEHOLDER}}`. Quote the value. |
| `RuntimeError: Aborted because --strict flag is set` | Not a bug: warnings were found above it. |
| Styles/JS 404 on GitHub Pages | `site_url` lacks the `/repo/` sub-path. Fix `site_url`. |
| Stale or odd output after an upgrade | Run `zensical build --clean`. |
| Tabs/grids render as plain text | Missing `pymdownx.tabbed` / `attr_list` + `md_in_html`, or no blank line around the block, or tab body not indented 4 spaces. |
| Nav item missing | Page not in `nav` (no warning is raised); run the audit script. |
